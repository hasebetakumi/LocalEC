# Handoff: 地域のお得情報アプリ「LocalEC」（仮称）フェーズ1

## 概要
栗橋地区（アケボノ様）の店舗が、商品の予約販売・イベント申し込み・求人応募・お知らせを掲載し、利用者がスマホで予約して店頭で受け取る（店頭払い）ための地域アプリ。
- **利用者アプリ**（スマホ・4タブ）：商品／イベント・求人／予約・申込／マイページ。お知らせはホーム右上のベル。
- **運営（スタッフ）画面**：スマホが主、PC は副。マイページの「スタッフメニュー」から入り、店舗を選んで「店舗モード」で操作。

## このバンドルの位置づけ
同梱の `*.dc.html` は **HTML で作ったデザイン参照（プロトタイプ）** です。そのまま製品コードとして使うものではありません。
実装タスクは、これらの画面を **対象コードベースの既存環境（React Native / Flutter / Next.js など）とその作法で再現する** ことです。まだ環境がない場合は、スマホアプリ＋運営 Web を無理なく両立できる構成（例：Expo + Next.js、または Flutter + Web）を選んでください。

HTML ファイルはブラウザで直接開けます（`support.js` が同じフォルダにあること）。各ページは Figma のようなキャンバスで、画面ごとに実機サイズ（390×844）のフレームと、その下に **実装上の補足メモ**（遷移先・ルール・初期値）が書かれています。**メモは仕様の一部です。必ず読んでください。**

## 忠実度
**High-fidelity（ピクセル忠実）**。配色・文字サイズ・余白・角丸・状態表現まで決定済み。各フレームのインラインスタイルがそのまま寸法の正です。
ただし以下は参照実装側の都合で、製品では置き換えてください。
- 写真は斜線のプレースホルダー → 実写真（アスペクト比・角丸はそのまま）
- フォントは Web 用に Noto Sans JP を読み込んでいる → アプリでは端末標準フォント（iOS ヒラギノ角ゴ、Android Noto Sans CJK）。端末の文字サイズ設定に追従させる
- 「‹」「×」「›」などの文字記号は一部に残っていても、実装は SVG/アイコンフォントで統一（06 の原則）

## ナビゲーション
**利用者（下タブ4つ）**
1. 商品：U-10 ホーム → U-10 一覧（すべて見る）→ U-12 商品詳細 → U-20 予約 → 完了。右上ベル → U-11 お知らせ一覧 → 詳細
2. イベント・求人：U-11（上部セグメント すべて／イベント／求人）→ U-12 → U-20 → 完了
3. 予約・申込：U-22（予約・申し込み中／履歴）→ U-22 予約詳細 → U-21 キャンセル確認（シート）
4. マイページ：登録情報変更、U-30 通知スイッチ、規約類、ログアウト、U-02 アカウント削除、**スタッフメニュー（スタッフ権限のみ表示）→ A-01**

**運営スマホ**：A-01 店舗を選ぶ（＋全店舗の番号検索）→ 店舗モード（ヘッダーに店舗名 ▾、下タブ3つ：掲載／予約・申し込み／店舗情報）
- 掲載：A-11 一覧 →（行）A-11 掲載詳細（予約一覧・右上「⋯」＝編集／複製／終了）／（＋掲載）種類メニュー → A-10 シート
- 予約・申し込み：A-20（初期値 本日×未完了）→ A-21 処理 → キャンセル確認シート
- 店舗情報：A-02（常に編集フォーム）
- 下階層（掲載詳細・A-21）はヘッダーの店舗名を出さず「‹ 戻り先名」のみ

**運営 PC**：ヘッダー右に店舗切替＋アバター（イニシャル丸、押すとメニュー）。左メニュー：商品・イベント・求人／予約・申し込み／店舗。A-10 の種類は PC ではフォーム内で選択（スマホのメニュー式にはしない）。

## 画面ごとの要点（詳細は各 HTML のフレームとメモ）
### 利用者
- **U-01**：パスワードなし。メールのマジックリンクでログイン／登録。登録は氏名・電話（必須、SMS 認証なし）・メール・規約同意。見るだけはログイン不要、「予約へ進む」で U-01 を挟む。
- **U-10 ホーム**：見出し「商品」＋ベル（未読バッジ）、カテゴリ7種の写真アイコン横スクロール、「もうすぐ終了！」「新着」の横スクロールカード（292px幅）、カテゴリ別帯。カード：写真150px、左上バッジ（半額／◯%OFF／新着／残りわずか／本日限定）、右上「残り◯食」、店舗名→商品名→受け取り時間→元値取り消し線＋割引後価格（24px 900 アクセント）。
- **U-10 一覧／U-13**：上部チップ「カテゴリ：すべて ▾」「店舗：すべて ▾」→ ボトムシートでカテゴリ（チップ・単一選択）／店舗（ラジオ）。キーワード検索なし。
- **U-11**：イベント・求人は 92px サムネ横並びカード、種類ラベルは写真左上、残りわずかは右下赤字。お知らせは日付・店舗・NEW、本文2行省略。
- **U-12 詳細**：写真（300/250px）→ 情報帯（残り数＋締切。求人は青で「受付中」）→ 店舗名・タイトル・価格 → 情報カード（受け取り時間／場所＋地図アプリで開く）→ 支払い（店頭で・チップ）／キャンセル可否／食品表示 → 下部固定バー（価格＋主ボタン）。締切後・売り切れ・定員到達はボタン無効＋理由表示（05）。
- **U-20**：商品＝数量、イベント＝人数（掲載ごとの上限）、求人＝確認のみ。＋−ステッパー（56px 丸）。確認カード（受け取り／場所／お支払い／キャンセル期限）。完了画面は種類色の全面地（商品 #B3471A、イベント #2E7D52、求人 #2F5F9E）＋白カードに 4桁番号（60px 900 字間 .14em）＋手順3つ。
- **U-22**：予約・申し込み中は **日付でグループ化**（今日は赤字）、点の色＝種類、右端に状態名＋番号。履歴は状態ピル＋タイトル＋日付。詳細は番号カード＋表（状態を1行目に）。キャンセルは赤テキストボタン → U-21 シート。
- **マイページ**：プロフィールカード（変更 ›）、スタッフメニュー（黒カード・スタッフのみ）、通知スイッチ1つ、リンク4つ、ログアウト／アカウント削除。
- **U-02**：受け取り前の予約があると削除不可（該当予約を表示、削除ボタンは無効色）。確認はシート。

### 運営
- **A-01**：店舗カード（公開中の掲載数／本日の予定件数）、「＋ 店舗を追加」（シート）、下に「番号で探す」（全店舗横断・前方一致）。
- **A-11 一覧**：チップ「すべての種類 ▾」「すべての状態 ▾」、件数＋並び順、**グループリスト**（1枚の白枠に区切り線）。行＝タイトル（左）＋予約数「8 / 20食」（右・15px 800）／2行目＝種類ラベル＋受け取り日時。状態ピルは **「公開」以外のときだけ**（公開予定／終了／下書き）。
- **A-11 ＋掲載**：ボタン直下にメニュー（商品／イベント／求人／お知らせ、アイコン付き）、背景暗転。選ぶと A-10 が下からシートで出る。
- **A-10 シート**：つまみ＋「×｜種類チップ＋◯◯を掲載」。種類はシート内で変更不可。入力欄は塗り。下部に「下書き保存」「公開する」。項目は DATA_MODEL.md。
- **A-11 掲載詳細**：種類・状態チップ、タイトル、受け取り時間＋「8 / 20食」、右上「⋯」（編集／複製／終了する）、番号検索、状態チップ「未完了 ▾」、予約リスト（番号 24px 等幅／名前＋数量／金額。未完了ピルは出さない）。
- **A-20**：番号検索（54px・白カード）、チップ「本日 ▾」「すべての種類 ▾」「未完了 ▾」（絞っているものは黒塗り）、件数行、グループリスト。行＝番号／名前＋**時間（右端・太字）**／種類ラベル＋内容。「未受け取り」など未完了ピルは出さず、完了・キャンセル・期限切れだけ2行目に。番号入力中は期間・状態の絞り込みが外れる。
- **A-21**：番号 60px、氏名、電話ピル（タップで発信）、表（状態／商品／お会計／受け取り）、緑のピル「受け取り済みにする」（確認なし1タップ、イベント＝参加済み、求人＝勤務済み）、赤テキスト「この予約をキャンセルにする」→ 下からシート（通知される旨を赤帯で）。受け取り済み画面には「未受け取りに戻す」。
- **A-02**：常に編集フォーム。支払い方法は複数選択チップ（✓付き黒塗り）。保存時、公開中商品の表示が変わる旨を確認。
- **A-12（05）**：予約が入った後は数量を減らす・受け取り期間・終了のみ編集可、他は鍵付き。

## インタラクション・振る舞い
- 画面遷移：push（左右）。シート（A-10／店舗追加／U-13／各確認）は下からスライド、背景 45〜55% 暗転、外側タップ・下スワイプで閉じる。入力途中のシートを閉じるときは「破棄しますか？」。
- 絞り込みチップ：タップでボトムシートの単一選択。選択値がデフォルト以外なら塗り（黒）。
- 「⋯」メニュー：iOS はアクションシート、Android はメニュー。
- ステッパー：残り数／上限で＋を無効化。0 未満不可。
- 主ボタンの押下中は 90% 不透明、無効は `#E5DFD6` 地＋`#6B635A` 文字（05 参照）。
- トランジションは 200〜250ms ease-out。派手なアニメーションは使わない。
- 通知（プッシュ／メール）：予約確定、受け取り前日・当日リマインド、店舗によるキャンセル・変更、お知らせ新着。U-30 のスイッチ1つで一括オン・オフ（Web 版では非表示）。
- 自動処理：公開期間による公開／終了、数量0・定員到達で締切（求人は締め切らない）、受け取り期間終了後の未受け取りを「期限切れ」に。

## 状態と表示名
利用者側と運営側で **同じ状態を別の名前で表示** します（DATA_MODEL.md の状態遷移を参照）。
| 内部 | 利用者（U-22） | 運営（A-20／A-21） |
|---|---|---|
| reserved（商品） | 予約済み | 未受け取り |
| reserved（イベント） | 申し込み済み | 未参加 |
| reserved（求人） | 応募済み | 未勤務 |
| completed | 受け取り済み／参加済み／勤務済み | 同左 |
| cancelled | キャンセル | キャンセル |
| expired | 期限切れ | 期限切れ |

掲載の状態：下書き／公開予定／公開／終了（公開予定は要件追加・確定済み）。

## 実装者向け補足
- 運営スマホが主。イベント・求人・お知らせの **入力フォーム（A-10）の種類別項目はスマホ版を未作成**。03 PC 版の種類別フォームの項目・順序を、04 のシート型レイアウト（塗り入力・52px）で再現してください。
- 削除済みユーザーの予約は、運営側で氏名を「削除済みユーザー」（斜体・グレー）で残す。
- 番号検索は 4桁の前方一致。A-01 では全店舗横断、A-11 詳細・A-20 では店舗内。
- PC の A-21 は確認ダイアログあり、スマホは1タップ（戻せるため）。
- 未決事項はありません（Q1〜Q25 全て確定、00 参照）。

## 推奨されるテスト（ユーザーテスト観点）
- スタッフが A-20・A-21 だけで当日の受け取り処理を完了できるか
- 番号 4桁の入力で目的の予約に 2 タップ以内で辿り着けるか
- 利用者が完了画面の番号を店頭で見せる動線（U-22 → 詳細）が迷わないか
