# 要件定義書（フェーズ1）

- 対象：地域EC（アケボノ様発）フェーズ1
- 作成：MeiN
- 状態：たたき台（アケボノ様との確認前）
- 関連文書：`proposal_slides.md`（提案書）、`技術選定.md`（技術構成）

## 1. 目的とスコープ

アケボノ様の自事業（カフェ、コインランドリー、幼稚園・保育園、農業）の商品・お得情報・お知らせをアプリで地域の生活者に届け、予約して取りに来てもらうことで売り切る。

**やること**：掲載、予約、店頭受け取り（現地決済）、お知らせ掲載、通知、検索・地図、運営向け管理画面

**やらないこと（フェーズ2以降）**：オンライン決済、LINEログイン、事業者ごとのアカウント、店舗フォロー、CSV出力、先着順キャンペーン、無断キャンセルへのペナルティ

## 2. 前提

| 項目 | 内容 |
| --- | --- |
| 利用者 | 誰でも登録できる公開アプリ。配布はまず職員から |
| 提供形態 | Expo で iOS・Android・Web を同時に提供 |
| 事業者 | アケボノ様のみ。複数の店舗（受け取り場所）を持つ |
| 入力担当 | アケボノ様スタッフ 3名程度 |
| 管理画面 | Web（PC向け）とアプリ内（スマホ向け）の両方で提供。同じ機能をExpoの1コードで出し、掲載入力はPC、QR読み取りはスマホが主な使い方 |
| 目標 | 開始半年後に利用者100人、掲載月30件 |
| 時期 | 2026年12月に職員でテスト運用、2027年1月に本番開始 |
| 決済 | 現地決済のみ。支払い方法（現金、PayPayなど）は店舗ごとに異なる |

データは「事業者 → 店舗 → 掲載」の階層で持ち、フェーズ2で事業者が増えても作り直さない。

## 3. 掲載する情報

次の3種類に分け、生活者の画面は「お得」「イベント・求人」「お知らせ」で分ける。

| 種類 | 内容 | 申し込み |
| --- | --- | --- |
| お得 | 弁当、お米、ドレッシング、ランドリーカード、ケーキ（いずれも自事業） | 数量を指定して予約し、店舗で受け取る |
| イベント・求人 | 子ども向けイベント、検診、脱穀などの日払い、アルバイト | 参加・応募を申し込む（定員あり） |
| お知らせ | 地域ニュースなど | なし。読むだけ |

## 4. 機能要件

### 生活者側

| No. | 機能 | 内容 |
| --- | --- | --- |
| U-01 | 登録・ログイン | 登録必須。メール＋パスワード、Appleでサインイン |
| U-02 | アカウント削除 | 利用者自身が削除できる（ストア審査で必須） |
| U-10 | お得一覧 | 写真、価格、残り数量、受け取り時間、店舗名を新着順に表示 |
| U-11 | イベント・求人一覧／お知らせ一覧 | それぞれ別タブで表示。イベント・求人は日時、場所、残り定員を示す |
| U-12 | 詳細 | お得：説明、受け取り場所・時間、支払い方法、予約締切、キャンセル可否、食品表示。イベント・求人：日時、場所、定員、申し込み締切、条件 |
| U-13 | 探す | カテゴリ・店舗での絞り込み、キーワード検索、地図表示 |
| U-20 | 予約・申し込み | お得は数量を指定して予約（1人あたりの上限なし）。イベント・求人は参加・応募を申し込む。残り数量・定員と締切を超えたら不可 |
| U-21 | キャンセル | 掲載ごとの設定に従い、期限内なら利用者がキャンセルできる。数量は戻る |
| U-22 | マイ予約 | 予約・申し込み中の一覧、履歴、受け取り用QRコードの表示（お得のみ） |
| U-30 | 通知 | 新着、予約・申し込み確定、受け取り・開催前リマインド。種類ごとにオン・オフ可。Web版は通知なし |

### 運営側（管理画面）

| No. | 機能 | 内容 |
| --- | --- | --- |
| A-01 | スタッフログイン | 生活者とは別のアカウント。スタッフでログインすると、アプリ内にスタッフ用メニューが表示される |
| A-02 | 店舗管理 | 名称、住所、地図位置、受け取り時間、支払い方法 |
| A-10 | 掲載入力 | お得：写真、価格、数量、店舗、受け取り時間、締切、キャンセル可否・期限、食品表示、公開開始・終了日時。イベント・求人：本文、日時、場所、定員、申し込み締切、公開期間。お知らせ：本文、公開期間 |
| A-11 | 公開管理 | 下書き・公開・終了の切り替え。公開期間による自動切り替え。数量0・定員到達で自動締切。過去の掲載の複製 |
| A-20 | 予約・申し込み一覧 | 掲載・店舗ごとに、誰が予約・申し込みしたかと状態を表示。手動で状態変更も可 |
| A-21 | QR読み取り | スマホでQRを読み取り、受け取り済みにする |
| A-22 | 無断キャンセル | 受け取り期限を過ぎた予約を自動で無断キャンセルにする。記録のみでペナルティなし |
| A-30 | 集計 | 期間・店舗ごとの予約数、受け取り数、売上を画面で表示 |

### 共通

- 予約・キャンセル・受け取りが同時に起きても残り数量が狂わない
- 特定商取引法に基づく表記、利用規約、プライバシーポリシー、問い合わせ先（アケボノ様）をアプリ内に置く

## 5. 基本の流れ

**生活者（お得）**：ホーム → 詳細 → 予約 → 通知（確定・リマインド） → 店舗でQRを見せる → その場で支払う

**生活者（イベント・求人）**：一覧 → 詳細 → 申し込み → 通知（確定・リマインド） → 当日参加

**運営**：掲載入力 → 公開 → 予約一覧で確認 → 店頭でQR読み取り → 集計

## 6. 非機能要件

| 項目 | 内容 |
| --- | --- |
| 対応端末 | iOS・Androidの直近2〜3バージョン。管理画面はPCブラウザとスマホアプリの両方 |
| セキュリティ | HTTPS。Supabaseの行レベルセキュリティで、生活者は自分の予約だけ、スタッフは自事業者の範囲だけ見られる |
| 性能・費用 | フェーズ1の規模はSupabase・Expoの無料枠で足りる想定。費用上限はなし |
| 運用 | 監視・不具合対応はMeiN。バックアップはSupabaseの自動バックアップ。配信はEAS Build／EAS Update |
| 品質 | 型チェック・Lint・テストをCIで必ず通す |
