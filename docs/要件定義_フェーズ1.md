# 要件定義書（フェーズ1）

- 対象：地域EC（アケボノ様発）フェーズ1
- 作成：MeiN
- 状態：たたき台（アケボノ様との確認前）
- 関連文書：`proposal_slides.md`（提案書）、`技術選定.md`（技術構成）

## 1. 目的とスコープ

アケボノ様の自事業（カフェ、コインランドリー、幼稚園・保育園、農業）の商品・お得情報・お知らせをアプリで地域の一般ユーザーに届け、予約して取りに来てもらうことで売り切る。

**やること**：掲載、予約、店頭受け取り（現地決済）、お知らせ掲載、通知、カテゴリ・店舗での絞り込み、運営向け管理画面

**やらないこと（フェーズ2以降）**：オンライン決済、LINEログイン、Appleでサインイン、事業者ごとのアカウント、店舗フォロー、地図表示、キーワード検索、QRコード受け取り、集計画面、無断キャンセルの自動処理、CSV出力、先着順キャンペーン、無断キャンセルへのペナルティ

## 2. 前提

| 項目 | 内容 |
| --- | --- |
| 利用者 | 誰でも登録できる公開アプリ。配布はまず職員から |
| 提供形態 | Expo で iOS・Android・Web を同時に提供 |
| 事業者 | アケボノ様のみ。複数の店舗（受け取り場所）を持つ |
| 入力担当 | アケボノ様スタッフ 3名程度。スタッフのアカウントは MeiN が Supabase 上で手作業で発行する（アプリ内に作成機能は持たない） |
| 管理画面 | Web（PC向け）とアプリ内（スマホ向け）の両方で提供。同じ機能をExpoの1コードで出し、掲載入力はPC、店頭での受け取り処理はスマホが主な使い方 |
| 目標 | 開始半年後に利用者100人、掲載月30件 |
| 時期 | 2026年12月に職員でテスト運用、2027年1月に本番開始 |
| 決済 | 現地決済のみ。支払い方法（現金、PayPayなど）は店舗ごとに異なる |

データは「事業者 → 店舗 → 掲載」の階層で持ち、フェーズ2で事業者が増えても作り直さない。

## 3. 掲載する情報

次の3種類に分け、一般ユーザーの画面は「お得」「イベント・求人」「お知らせ」で分ける。

| 種類 | 内容 | 申し込み |
| --- | --- | --- |
| お得 | 弁当、お米、ドレッシング、ランドリーカード、ケーキ（いずれも自事業） | 数量を指定して予約し、店舗で受け取る |
| イベント・求人 | 子ども向けイベント、検診、脱穀などの日払い、アルバイト | イベントは参加を申し込む（定員あり。申し込みで確定）。求人は応募を受け付けるだけで、採否はアケボノ様がアプリ外で連絡する |
| お知らせ | 地域ニュースなど | なし。読むだけ |

## 4. 機能要件

### 一般ユーザー側

| No. | 機能 | 内容 |
| --- | --- | --- |
| U-01 | 登録・ログイン | 予約・申し込みには登録が必要（見るだけならログイン不要）。パスワードは使わず、メールに届くリンクを押してログイン・登録する。登録時に氏名と電話番号を入力（受け取り時の確認と連絡用）。パスワードがないため再設定の機能は持たない |
| U-02 | アカウント削除 | 利用者自身が削除できる（ストア審査で必須）。削除時は氏名・電話番号・メールなどの個人情報を消し、予約・申し込みの記録は「削除済みユーザー」として残す（運営側の履歴・合計金額が変わらないようにする） |
| U-10 | お得一覧 | 写真、価格、残り数量、受け取り時間、店舗名を新着順に表示 |
| U-11 | イベント・求人一覧／お知らせ一覧 | それぞれ別タブで表示。イベント・求人は日時、場所、残り定員を示す |
| U-12 | 詳細 | お得：説明、受け取り場所・受け取り期間、支払い方法、予約締切、キャンセル可否、食品表示。イベント：日時、場所、定員、料金、申し込み締切、キャンセル可否、条件。求人：日時、場所、募集人数、報酬、応募締切、キャンセル可否、条件 |
| U-13 | 絞り込み | カテゴリ・店舗で絞り込む。詳細には住所と「地図アプリで開く」リンクを置く |
| U-20 | 予約・申し込み | お得は数量を指定して予約（1人あたりの上限なし）。イベントは人数を指定して申し込む（指定できる人数の上限は掲載ごとに設定。上限1なら人数入力なし）。求人は応募する。残り数量・定員と締切を超えたら不可。求人は募集人数を表示するだけで、到達しても応募は締め切らない |
| U-21 | キャンセル | 掲載ごとの設定（可否・期限）に従い、期限内なら利用者がキャンセルできる。数量・定員は戻る。お得・イベント・求人のいずれも同じ |
| U-22 | マイ予約 | 予約・申し込み中の一覧、履歴、予約番号の表示。受け取り時は予約番号と名前を店舗で伝える |
| U-30 | 通知 | 新着、予約・申し込み確定（求人は「応募を受け付けました」）、受け取り・開催前リマインド、運営による受け取り期間の変更・キャンセル。アプリ内のオン・オフは1つ（種類ごとの設定はOSに任せる）。Web版は通知なし |

### 運営側（管理画面）

| No. | 機能 | 内容 |
| --- | --- | --- |
| A-01 | スタッフログイン | 一般ユーザーとは別のアカウント。ログイン方法は一般ユーザーと同じメールのリンク。アカウントは MeiN が Supabase 上で手作業で発行し、アプリ内に作成・招待の機能は持たない。スタッフでログインすると、アプリ内にスタッフ用メニューが表示される |
| A-02 | 店舗管理 | 名称、住所、営業時間、支払い方法。受け取り時間は店舗ではなく掲載ごとに持つ |
| A-10 | 掲載入力 | お得：写真、価格、数量、店舗、受け取り期間（開始・終了日時）、予約締切、キャンセル可否・期限、食品表示、公開開始・終了日時。イベント：本文、日時、場所、定員、1件の申し込みで指定できる人数の上限、料金、申し込み締切、キャンセル可否・期限、公開期間。求人：本文、日時、場所、募集人数、報酬、応募締切、キャンセル可否・期限、公開期間。お知らせ：本文、公開期間 |
| A-11 | 公開管理 | 下書き・公開・終了の切り替え。公開期間による自動切り替え。数量0・定員到達で自動締切（求人は締め切らない）。過去の掲載の複製。公開時に新着通知を送るかどうかを選べる |
| A-12 | 予約が入った後の変更 | 予約・申し込みが1件でも入った掲載は削除できない。できる変更は、数量・定員を減らす（予約済みの数より下には減らせない）、受け取り期間・日時を変える、終了する、の3つ。終了しても既存の予約は残り、受け取りまで進める。受け取り期間・日時を変えたときは予約者に通知する |
| A-20 | 予約・申し込み一覧 | 掲載・店舗ごとに、誰が予約・申し込みしたかと状態を表示。お得は件数と合計金額、イベントは申し込み人数の合計を上部に出す |
| A-21 | 受け取り処理 | お得のみ。一覧から予約をタップして受け取り済みにする。キャンセルへの変更も可（利用者に通知する）。イベント・求人は当日の出欠を記録しない |
| A-22 | 期限切れ表示 | お得のみ。受け取り期間の終了日時を過ぎて未受け取りの予約は一覧で「期限切れ」と表示する（無断キャンセル扱い。ペナルティなし） |

### 共通

- 予約・キャンセル・受け取りが同時に起きても残り数量が狂わない
- 特定商取引法に基づく表記、利用規約、プライバシーポリシー、問い合わせ先（アケボノ様）をアプリ内に置く

## 5. 基本の流れ

**一般ユーザー（お得）**：ホーム → 詳細 → 予約 → 通知（確定・リマインド） → 店舗で予約番号を伝える → その場で支払う

**一般ユーザー（イベント）**：一覧 → 詳細 → 人数を指定して申し込み → 通知（確定・リマインド） → 当日参加

**一般ユーザー（求人）**：一覧 → 詳細 → 応募 → 通知（受け付け） → アケボノ様からアプリ外で採否の連絡

**運営**：掲載入力 → 公開 → 予約一覧で確認 → 店頭で受け取り済みにする

## 6. 非機能要件

| 項目 | 内容 |
| --- | --- |
| 対応端末 | iOS・Androidの直近2〜3バージョン。管理画面はPCブラウザとスマホアプリの両方 |
| セキュリティ | HTTPS。Supabaseの行レベルセキュリティで、一般ユーザーは自分の予約だけ、スタッフは自事業者の範囲だけ見られる |
| 性能・費用 | フェーズ1の規模はSupabase・Expoの無料枠で足りる想定。費用上限はなし |
| 運用 | 監視・不具合対応はMeiN。バックアップはSupabaseの自動バックアップ。配信はEAS Build／EAS Update |
| 品質 | 型チェック・Lint・テストをCIで必ず通す |
