# 設計：デプロイ（お客さんに見せるための公開）

作成 2026-10-13。お客さんに触ってもらうための公開方針。**見せ方は、自分（長谷部）の iPhone と Android を渡して触ってもらう**。お客さんの端末に入れてもらうことは前提にしないが、Web 版はお客さんの端末でも開ける。ストア配布とネイティブビルドの配布は別の設計で扱う。

## 1. 目的と範囲

- 渡した 2 台で、利用者画面と運営画面を一通り触れる状態にする（ログイン・予約・キャンセル・運営の操作・通知まで）
- 手元の PC や自宅の LAN がなくても動くこと。お客さんの事務所など、どこでも見せられる
- 配布は **Expo Go + EAS Update** と **Web 版** の両方。Web 版は URL 1 つで見せられるので、お客さんが後で自分の端末から見返すときにも使う
- 範囲外：ストア申請、EAS Build での配布、プッシュ通知の本番運用（APNs・FCM の登録）

## 2. 結論（方針）

| 項目         | 方針                                                                                            | 理由                                                                                                                           |
| ------------ | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| バックエンド | Supabase のホスト版プロジェクトを 1 つ作る（東京リージョン、まず Free）                         | ローカルの Docker は自宅の LAN の外から届かない。これだけはどの見せ方でも必須                                                  |
| メール       | Resend で送信元ドメインを認証し、ログインリンクと通知のメールをどのアドレスにも送れるようにする | ログインの流れ自体を見せられる。お客さんが自分のアドレスで登録・ログインでき、確定メールも自分の受信箱で確かめられる           |
| アプリ版     | `expo-updates` を入れて `eas update --channel preview`、自分の Expo Go で開く                   | 一度公開すれば PC は不要。Expo Go は自分のアカウント（meincoltd）でログイン済みなので、SDK 57 のログイン必須の制約に当たらない |
| Web 版       | `npx expo export --platform web` → EAS Hosting（`eas deploy`）                                  | EAS のアカウントが既にあり、プレビュー URL は追加契約なしで出せる。独自ドメインは有料プランなので今は使わない                  |
| 端末の役割   | 分けない。どちらの端末でも利用者・運営の両方を触れる                                            | 動作確認手順と同じく 1 つのアカウントで両方の役を演じる。端末ごとに役を固定しない                                              |
| 環境の数     | 「ローカル」と「デモ（お客さん用）」の 2 つ                                                     | 本番はまだない。デモ環境は本番に昇格させず、本番は別に作る                                                                     |

### 2.1 先に知っておくべき制約

1. **Android の Expo Go と Web ではプッシュ通知が動かない**。プッシュは iPhone の Expo Go で見せる（通知の設計 15 章で受信を確認済み）。他ではメール通知が届くことで代える
2. **iPhone の Expo Go で開くには、Expo Go と公開したアカウントが同じであること**。自分の端末なので満たせる。渡す前にログアウトしないこと
3. **Supabase Free は 7 日間アクセスがないと停止する**。見せる前日に起こすか、デモ期間だけ Pro（月 25 ドル）にする
4. **Expo Go 向けの `runtimeVersion` は `{"policy": "sdkVersion"}`**。Expo Go は SDK ごとのランタイム（`exposdk:57.0.0`）しか読まない。後で開発ビルドに移るときに `appVersion` か `fingerprint` に替える
5. **端末を渡すので、端末に残る情報に注意**。Expo Go の他プロジェクト、受信箱、ブラウザのタブなどは事前に片付ける
6. Resend の Free は 1 日 100 通。`auth.rate_limit.email_sent = 100` はこれに合わせてある。ドメイン認証後も上限は同じ

## 3. 構成

```
自分の iPhone ─ Expo Go ─┐
自分の Android ─ Expo Go ─┤─ EAS Update（channel: preview、runtime: exposdk:57.0.0）
どの端末のブラウザ ─ https://<slug>.expo.app（EAS Hosting、静的書き出し）
                     │
                     ▼
      Supabase ホスト版（https://<ref>.supabase.co）
       ├─ Postgres（マイグレーション・シード・pg_cron・Vault）
       ├─ Auth（マジックリンク。SMTP は Resend、認証済みドメインから送信）
       ├─ Storage（listing-photos。シード写真は seed buckets で投入）
       └─ Edge Function send-notifications（プッシュは Expo Push API、メールは Resend）
```

### 3.1 環境変数の持ち方

| 場所                                                                         | ローカル                                                    | デモ                                                                                                                                                                  |
| ---------------------------------------------------------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| アプリ（`EXPO_PUBLIC_SUPABASE_URL`・`EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`） | `app/.env`                                                  | `app/.env.production`（Git に入れない。`.env.production.example` を置く）。`eas update` と `expo export` は `NODE_ENV=production` で動くので自動でこちらを読む        |
| 関数の秘密（`CRON_SECRET`・`SMTP_*`・`MAIL_FROM*`・`APP_WEB_URL`）           | `app/supabase/.env`                                         | `npx supabase secrets set`（設計_通知の配信 7 章）。`MAIL_FROM` は認証済みドメインのアドレスにする。`APP_WEB_URL` は Web の公開 URL（4 章 C）                         |
| Auth の SMTP パスワード・送信元                                              | `config.toml` の `env(SMTP_PASS)`・`env(MAIL_FROM_ADDRESS)` | `supabase config push` のときに同じ環境変数を読む。ローカルと同じ `supabase/.env` を使う（ドメイン認証後は `MAIL_FROM_ADDRESS` もローカルで認証済みドメインに替える） |
| Vault（`functions_url`・`publishable_key`・`cron_secret`）                   | `seed.sql` がローカル用の値を入れる                         | **シード後に Studio の SQL で 3 つを上書きする**（`vault.update_secret`）。忘れると pg_cron から関数が呼ばれず、通知が出ない                                          |

### 3.2 認証のリダイレクト先

`authRedirectUrl()` は `Linking.createURL('/auth/confirm')` なので、Expo Go なら `exp://u.expo.dev/...`、Web なら公開 URL になる。`config.toml` の `additional_redirect_urls` は `exp://**` と `localec://**` が既にある。Web の公開 URL（`https://<slug>.expo.app/**`）を足し、`site_url` もそれにする（`config push` で反映）。Web の URL は `eas deploy` の初回で決まるので、先に Web を出してから `config push` する。

### 3.3 メールの送信元

- Resend の Domains に `dev.localec.meincoltd.com` を登録し、表示された SPF・DKIM（と必要なら DMARC）を DNS に入れる（DNS は長谷部が触る）
- `MAIL_FROM` は `LocalEC <no-reply@dev.localec.meincoltd.com>`。ログインのメール（Auth の `admin_email`）と通知のメール（関数の `MAIL_FROM`）で同じにする
- 本番では先方のドメインに替える。設定は `supabase/.env`（ローカル）と `secrets set`・`config push`（ホスト版）の 2 か所

### 6.1 長谷部の手順（ダッシュボード）

**Resend**

1. https://resend.com/domains で「Add Domain」→ `dev.localec.meincoltd.com`、リージョンは Tokyo

**Supabase**

1. https://supabase.com/dashboard で「New project」。組織は会社のもの、名前は `localec-dev`、リージョンは Northeast Asia (Tokyo)、プランは Free。DB のパスワードは控えておく（`supabase link` で聞かれる）

3. CLI の作業が終わったら、SQL Editor で Vault の 3 つを上書き（Claude が SQL を用意する）

## 8. 今後の課題（ストア配布に進むとき）

- **ログインのリンクで一瞬ブラウザが開く**。メールのリンクは https の URL（Supabase の確認用 URL）で、メールアプリはそれをブラウザに渡し、ブラウザがトークンを検証してからアプリのスキーム（`localec://`）へ戻る。マジックリンク方式のアプリでは一般的な挙動で、Expo Go の間は避けられない。消すには iOS の Universal Links・Android の App Links を使う。アプリと紐づけた https のリンクなら OS が直接アプリを開く。必要なもの：(1) 自分のドメインに検証用ファイル（iOS は `apple-app-site-association`、Android は `assetlinks.json`）を置く、(2) Expo Go では使えないので開発ビルドかストア配布のビルド、(3) Supabase のリダイレクト先をそのドメインにする。Expo の設定は `ios.associatedDomains` と `android.intentFilters`（https://docs.expo.dev/linking/ios-universal-links/ 、https://docs.expo.dev/linking/android-app-links/ ）
