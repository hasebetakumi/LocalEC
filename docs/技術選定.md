# 技術選定

iOS・Androidアプリとして開発する前提で、生成AIを活用した少人数開発に最適な構成を定める。

## 結論

**Expo（React Native）+ TypeScript + Supabase** を採用する。

## 選定基準

- **生成AIが得意な言語**：TypeScript／React系は事例が最も多く、AIの出力精度が高い
- **全体を1言語に統一**：アプリ・管理画面・バックエンドを同じ言語にし、AIに一気通貫で変更を任せられる
- **型とテストで守る**：AIの生成コードの誤りを型チェックとCIで機械的に弾く
- **枯れた技術**：情報が多く、AIの知識が追いつく技術を選ぶ

## 構成

| 層 | 採用技術 | 理由 |
| --- | --- | --- |
| アプリ | Expo（React Native）+ TypeScript | 1コードでiOS・Android・Web版を出せる |
| 管理画面 | Expo（同じアプリ内） | スタッフでログインするとスタッフ用メニューが出る。PC ブラウザとスマホアプリの両方で使う |
| バックエンド | Supabase（DB・認証・ストレージ） | サーバー構築不要で実費が小さい。地域ごとのデータ分離で横展開に対応 |
| 通知 | Expo Notifications | 新着、予約・申し込み確定、リマインド、受け取り期間の変更を配信 |
| 決済（フェーズ2） | Stripe | 実物商品のためストア課金の対象外 |
| 配信 | EAS Build／EAS Update | 軽微な修正はストア審査なしで配信 |

Web版も同時に出せるため、SEO対策やLINEからのリンク共有にそのまま使える。

## 決済とストア規約

| 売るもの | 例 | 決済手段 |
| --- | --- | --- |
| デジタル商品 | Spotifyの有料プラン、有料機能 | ストア課金が必須（手数料15〜30%） |
| 実物商品・サービス | 弁当・米・野菜の予約購入 | Stripeなど外部決済を使う（手数料3.6%前後） |

- 一般ユーザーの商品購入は実物商品なのでStripeで問題ない。Uber EatsやAmazonと同じ扱い
- アプリ内で決済を完結できる。StripeのPayment Sheetで、カード・Apple Pay・Google Payをその場で支払える
- 事業者の月額や掲載料はデジタルサービス扱いになるため、アプリには載せずWeb管理画面や請求書で処理する

## 代替案と不採用の理由

- **Flutter + Firebase**：UI品質は高いが、Web版・SEOが弱く、管理画面が別言語になる
- **Swift／Kotlin（ネイティブ）**：コードが2つになり、この規模では維持コストが見合わない

## 開発の進め方

- アプリと管理画面は1つの Expo プロジェクト（`app/`）にまとめる（管理画面をアプリ内に出すため、モノレポは不要）。ドキュメントやスクリプトとは分けて管理する。Supabase の型定義は CLI で生成してアプリから参照する
- リポジトリに開発ルール（`CLAUDE.md`、`app/AGENTS.md`）を置き、AIに毎回読ませる
- 型チェック・Lint・テストをCIで必ず通す
- Supabase・Expo・Stripeはいずれも無料枠から始め、初期費用ゼロの方針と揃える

## 開発環境（2026-10-05 構築）

| 項目 | 採用 | 備考 |
| --- | --- | --- |
| Expo SDK | 57 | React Native 0.86、React 19.2、TypeScript 6.0 は SDK が対応版を固定する。npm の最新版ではなく `npx expo install` が選ぶ版を使う |
| ルーティング | Expo Router | `app/src/app/` 配下のファイルが画面。テストなど画面以外は `app/src/app/` の外に置く |
| Lint・整形 | ESLint 9（eslint-config-expo）+ Prettier | eslint-config-expo が eslint 9 系前提のため、eslint 10 は使わない |
| テスト | Jest 29 + jest-expo + Testing Library v14 | jest-expo 57 の内部が jest 29 系のため、jest 30 は使わない。Testing Library v14 は `render` が非同期 |
| CI | GitHub Actions | 型チェック・Lint・整形・テストを PR ごとに実行 |
| ローカル環境 | WSL2（mirrored ネットワーク）+ Node.js 22 + Docker | Android エミュレータは入れず、実機の Expo Go と Web ブラウザで確認 |
