# 実装設計：認証メール（ログイン・メールアドレス変更）のデザイン

Supabase Auth が送る 2 種類のメール（マジックリンク、メールアドレス変更の確認）を、アプリと同じ配色・部品で整える。
現状は `h2` と `p` と `a` だけの素の HTML で、メーラーの既定表示になっている（見た目は未着手。[設計_利用者予約フロー_U10-U12-U20.md](設計_利用者予約フロー_U10-U12-U20.md) 付録 C は「押せるリンクにする」ことだけを扱った）。

**実装状況（2026-10-13）**：実装済み（ブランチ `feature/user-booking-flow`）。`app/supabase/templates/` の 2 ファイルは付録 A・B を Prettier（`npm run format:check` の対象）で整形したもので、内容は同じ。以後はファイル側を正とする。確認済み：ダミー値を入れた Chromium 描画（幅 390・1000）、ローカル Auth からの送信（テンプレート読み込み・送信とも成功、`ZgotmplZ` なし）。未確認：5 章 3〜6 の実際の受信箱での見た目（Gmail・iOS メール・ダークモード）、ボタンからのログイン復帰、メールアドレス変更の通し操作。

この文書だけで実装に着手できるように書いてある。付録 A・B の HTML を正とし、迷ったら 2 章の制約と 3 章の仕様に戻る。

- 配色・部品の正：`design/06_デザインルール.dc.html`、[設計_利用者予約フロー_U10-U12-U20.md](設計_利用者予約フロー_U10-U12-U20.md) 付録 A.1（`src/theme/tokens.ts`）

## 2. メール HTML の制約（先に読む）

アプリの画面と違い、メールは次の制約の中で作る。付録の HTML はこれを守って書いてある。変更するときも守る。

### 2.1 Supabase（Go の `html/template`）由来

- 本文は Go の `html/template` で組み立てられる。`{{ .ConfirmationURL }}` 以外の場所で `{{` を書かない（CSS の `{` 1 つは問題ない）
- `href` に入れられるのは `http`・`https`・`mailto` で始まる URL だけ。それ以外は `ZgotmplZ` に置き換わる。アプリへの戻り先（`exp://`、`localec://`）はテンプレートに直接書かず、`{{ .ConfirmationURL }}` に任せる（付録 C と同じ）
- 使える変数：`{{ .ConfirmationURL }}`（押すリンク）、`{{ .Email }}`（送信先。email_change では変更前のアドレス）、`{{ .NewEmail }}`（email_change の新しいアドレス）、`{{ .SiteURL }}`。変数は自動で HTML エスケープされる
- 件名は `config.toml` の `subject`。本文ファイルからは変えられない

### 2.2 メーラー由来

- **CSS はすべてインライン**。`<style>` ブロックは Gmail（Web・アプリ）で一部しか効かず、Outlook は無視する。付録では `<style>` を使わない
- **レイアウトは `table`**。`display:flex`・`grid`・`position` は使わない。中央寄せは `<td align="center">`
- 背景色は `style="background:…"` と `bgcolor="…"` の両方に書く（Outlook は属性しか見ない）
- `border-radius` は Outlook（Windows）では角丸にならず四角になる。許容する（利用者はスマホの Gmail／iOS メールが中心）
- 画像は外部ホスティングが必要で、Gmail は初回ブロックすることがある。**本書では画像を使わない**（ワードマークは文字）
- JavaScript・フォーム・Web フォントは使えない。フォントは端末の標準（3.4）
- 幅は 480px を上限にし、スマホでは全幅。`<meta name="viewport">` を入れる
- Gmail は本文が約 102KB を超えると末尾を切る。付録の HTML は 5KB 程度
- ダークモード：Apple メールは `<meta name="color-scheme" content="light">` でライト表示を維持する。Gmail アプリは独自に色を反転することがある（5 章で確認し、文字が読めればよい）

## 3. デザイン仕様

### 3.1 骨組み

生成りの地（`bg`）の上に白いカード（`card`）を 1 枚置き、カードの中に見出し・本文・主ボタン・補足を縦に並べる。カードの上にワードマーク、下にフッター。アプリの画面（U-01 ログイン）と同じ印象にする。

```
┌──────────────────────────────────────────┐  bg #F6F1E8（全幅）
│   余白 32                                 │
│   LocalEC                 ← ワードマーク   │  15/800 accent、字間 .08em、左寄せ
│   余白 16                                 │
│  ┌────────────────────────────────────┐  │  card #FFFFFF、角丸 18、内側 28×24
│  │ LocalEC にログイン        ← 見出し  │  │  22/800 text
│  │ 下のボタンを押すと…       ← 本文    │  │  15/400 textSub、行間 1.7
│  │                                    │  │
│  │     ┌──────────────────┐            │  │  主ボタン：accent 塗り、白文字、ピル型
│  │     │   ログインする    │ ← 中央     │  │  17/700、padding 16×36（高さ約 52）
│  │     └──────────────────┘            │  │
│  │ 有効期限は 15 分。送った端末で… ← 補足 │  │  13/400 textWeak、中央
│  │ ────────────────────────────────── │  │  divider #F0EBE4
│  │ ボタンが押せないときは…  ← URL 控え  │  │  13/400 textWeak、URL は accent で折り返し
│  └────────────────────────────────────┘  │
│   余白 20                                 │
│   このメールは … へ送信しました ← フッター │  12/400 textWeak、行間 1.7
│   余白 32                                 │
└──────────────────────────────────────────┘
   最大幅 480、左右の外側余白 16
```

### 3.2 配色（`src/theme/tokens.ts` と同じ値）

| 用途                               | トークン   | 値        |
| ---------------------------------- | ---------- | --------- |
| メール全体の背景                   | `bg`       | `#F6F1E8` |
| カード                             | `card`     | `#FFFFFF` |
| 見出し                             | `text`     | `#1F1B17` |
| 本文                               | `textSub`  | `#4A443D` |
| 補足・フッター                     | `textWeak` | `#6A6159` |
| 区切り線                           | `divider`  | `#F0EBE4` |
| ワードマーク・主ボタン・リンク     | `accent`   | `#B3471A` |
| 主ボタンの文字                     | 白         | `#FFFFFF` |
| アドレス表示の塗り（email_change） | `fill`     | `#EFE9DF` |

白文字を載せる `#B3471A` はコントラスト比 4.5:1 以上（デザインルール 06 で確認済み）。`#6A6159` を白地に載せた本文も 4.5:1 以上。

### 3.3 ワードマーク

ロゴ画像はまだ外部に置ける場所がないので、文字「LocalEC」を `accent` の 15/800・字間 .08em で置く（デザインルール 06 の見出し上のラベルと同じ扱い）。サービス名が正式に決まったら、ここと件名・`sender_name`・フッターの 4 か所を同時に変える。ロゴ画像をホスティングできるようになったら `<img>` に差し替え、`alt="LocalEC"` を付け、高さ 24px 程度にする。

### 3.4 文字

- フォント指定（インラインで毎回書く）：`-apple-system, BlinkMacSystemFont, "Hiragino Sans", "Hiragino Kaku Gothic ProN", "Noto Sans JP", "Noto Sans CJK JP", Meiryo, sans-serif`。端末の標準フォントに乗せる（デザインルール 06 と同じ方針）
- サイズ：見出し 22/800、本文 15/400、ボタン 17/700、補足 13、フッター 12。本文は 15 以上、最小 12（アプリの利用者画面と同じ下限）
- 行間：本文 1.7、見出し 1.4
- 数字と単位の間は半角スペース（「15 分」）。アプリ内の文言と揃える

### 3.5 ボタン

- 1 通に主ボタンは 1 つ。`accent` の塗り・白文字・ピル型（`border-radius:999px`）。枠線ボタンは使わない（デザインルール 06）
- `<a>` を `display:inline-block` にし、`padding:16px 36px` で押しやすい高さ（約 52px）にする。外側の `<td>` にも `bgcolor` と `border-radius` を書く（Outlook は `<a>` の padding を無視するため、`<td>` の塗りが保険になる）
- ボタンのすぐ下に、URL をそのまま書いた「控え」を置く。ボタンが効かないメーラー（テキスト表示、一部の企業メール）向け。`word-break:break-all` で折り返す

### 3.6 文面

言葉遣いはアプリの画面（U-01、送信後画面 `src/app/auth/sent.tsx`）に合わせる。「押す」「送った端末で開く」「15 分」をそろえる。

**ログイン（magic_link / confirmation）**

| 部位         | 文言                                                                                                                                                                      |

| 件名         | `LocalEC ログイン用リンク`（現状のまま）                                                                                                                                  |

| 見出し       | `LocalEC にログイン`                                                                                                                                                      |

## 4. ファイル構成と設定

変えるのは 2 ファイルだけ。`config.toml` は現状の参照先のままでよい。

| ファイル                                   | 内容                                        |
| ------------------------------------------ | ------------------------------------------- |
| `app/supabase/templates/magic_link.html`   | 付録 A（magic_link と confirmation が共用） |
| `app/supabase/templates/email_change.html` | 付録 B                                      |

```toml
# app/supabase/config.toml（現状のまま。変更不要）
[auth.email.smtp]
sender_name = "LocalEC"                   # 差出人名。サービス名が変わったらここも

[auth.email.template.magic_link]
subject = "LocalEC ログイン用リンク"
content_path = "./supabase/templates/magic_link.html"

[auth.email.template.confirmation]
subject = "LocalEC ログイン用リンク"
content_path = "./supabase/templates/magic_link.html"

[auth.email.template.email_change]
subject = "LocalEC メールアドレス変更の確認"
content_path = "./supabase/templates/email_change.html"
```

**本番（Supabase ダッシュボード）**：Authentication → Email Templates で、Magic Link と Confirm signup に付録 A、Change Email Address に付録 B を貼り、件名も上の値にする。ダッシュボードのテンプレートは `config.toml` と同期しないので手作業。差出人名は Project Settings → Auth → SMTP Settings の Sender name。

## 5. 確認手順

ローカルでも Resend で本物の受信箱に送る（README「メール（Resend）」。送信元ドメイン認証前は `t-hasebe@meincoltd.com` にしか届かない）。

## 7. 後続・未決

- **サービス名**：「LocalEC」は仮称。決まったら件名・`sender_name`・ワードマーク・フッターを同時に変える
- **ロゴ画像**：ホスティング先（Supabase Storage の公開バケット、または Web 版のドメイン）が決まったらワードマークを画像にする（3.3）
- **通知メールの HTML 化**：[設計_通知の配信.md](設計_通知の配信.md) の `send_email` 関数に `html` を足すとき、付録 A の骨組み（背景・カード・ボタン・フッター）をそのまま使う。本文だけ差し替える
- **送信元ドメインの認証**：Resend で独自ドメインを認証するまで、他のアドレスには届かない。認証後は `MAIL_FROM_ADDRESS` を `no-reply@<ドメイン>` にする
- **問い合わせ先**：フッターに運営の連絡先（店舗名・電話）を入れるかは未決。入れる場合は `{{ .SiteURL }}` ではなく固定文言にする（SiteURL は localhost になるため）
