# 実装設計：通知メール（予約確定・リマインド・キャンセル・変更）のデザイン

Edge Function `send-notifications` が送る取引通知のメールを、[設計_認証メールのデザイン.md](設計_認証メールのデザイン.md) と同じ骨組み（生成りの地、白いカード、テラコッタのピル型ボタン）の HTML にする。
現状は `subject` と `text` だけの素のテキストメール（[設計_通知の配信.md](設計_通知の配信.md) 6 章）。

**実装状況（2026-10-14）**：実装済み（ブランチ `fix/bug-fixes`）。`helpers.ts` に `emailContent`（HTML 付き）・`emailLink`・`escapeHtml`・`NUMBER_BOX_KINDS`、`index.ts` で予約の番号と種類を 1 回で引いて渡す。確認済み：Jest（5 章の項目すべて）、ヘッドレス Chromium の描画（確定・リマインド（ボタンなし）・店舗キャンセル・期間変更（ボタンなし）を幅 390・1000）、ローカルの関数から Resend への送信（確定、ボタンなし。`email_error` なし）。未確認：6 章 3〜8 の実際の受信箱での見た目（Gmail・iOS メール・ダークモード）、ボタンからの Web 版の予約詳細への遷移、`multipart/alternative` になっていること

この文書だけで実装に着手できるように書いてある。迷ったら認証メールの設計書 2 章（メール HTML の制約）と、本書 3 章の仕様に戻る。

- 骨組み・配色・文字の正：認証メールの設計書 2・3 章と `app/supabase/templates/magic_link.html`。本書では差分だけ書く
- 文言の正：`title`・`body` は DB のトリガー・関数（SQL）が作る（設計_通知の配信 5 章）。**本書では文面を変えない**。HTML は枠と部品を足すだけ
- 番号の箱の見た目の正：`src/components/NumberCard.tsx`（アプリの予約完了・予約詳細）

## 1. 範囲

| 含める                                                                                                           | 含めない（後続）                                                                    |
| ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| メールで送る通知 4 種：`booking_confirmed`・`reminder`・`cancelled_by_staff`・`listing_changed`                  | `title`・`body` の文面（SQL 側。変えるなら設計_通知の配信を先に直す）               |

| 件名はそのまま、`text` も残して `html` を足す（マルチパート）                                                    | ロゴ画像（認証メールと同じく文字のワードマーク）                                    |
| ボタンの先（Web 版の URL）を環境変数で渡す                                                                       | アプリを直接開くリンク（Universal Links。設計_デプロイ 8 章）                       |

## 2. 判断した点

1. **文面は DB のまま、HTML は枠だけ足す**。プッシュとメールで同じ `title`・`body` を使っているので、メール側で文を作り直すと二重管理になり、表記ズレ（[調査_利用者画面と運営画面のズレ.md](調査_利用者画面と運営画面のズレ.md)）の温床になる。例外は「番号の箱」で、これは `bookings.number` という 1 つの値を目立たせるだけなので許容する
2. **番号の箱は「番号を店で見せる場面」の 2 種だけ**（確定・リマインド）。キャンセルや変更のメールで番号を大きく出すと、まだ有効な予約に見える
3. **ボタンは Web 版へのリンク**。メールからアプリ（Expo Go）を直接は開けない。Web 版は URL 1 つで開けてログイン後は押した画面に戻る（`feature/user-booking-flow` で実装済み）ので、受信箱から予約詳細に行ける。Web の URL は `eas deploy` の初回で決まる（設計_デプロイ 4 章 C）ため環境変数にし、**未設定ならボタンを出さない**（文章だけで成立させる）
4. **件名は `【LocalEC】<title>` のまま**。認証メールの件名は `LocalEC ログイン用リンク` で形が違うが、通知は `title` が可変なので括弧で区切る方が受信箱で読みやすい。サービス名が決まったときに 4 か所（認証 2・通知 1・`sender_name`）を同時に見直す
5. **`text` を残す**。テキスト表示しかしないメーラーと迷惑メール判定のため。`html` と `text` の両方を `sendMail` に渡すと nodemailer がマルチパートにする
6. **種類ごとの色分けはしない**。アプリでは種類（商品・イベント・求人）に色があるが、メールは 1 通 1 件で比較する場面がないので、認証メールと同じ `accent` 1 色で揃える。キャンセルも `danger` 色にしない（見出し文で伝わる）
7. **HTML エスケープは必ず通す**。`title`・`body` には掲載名（運営が自由に入力）が入る。`<`・`&` などをそのまま出すと崩れる・差し込まれる

## 3. デザイン仕様

### 3.1 骨組み

認証メールの 3.1 と同じ。カードの中身だけ次の順に置く。

```
┌──────────────────────────────────────────┐  bg #F6F1E8（全幅）
│   余白 32                                 │
│   LocalEC                 ← ワードマーク   │  15/800 accent、字間 .08em
│   余白 16                                 │
│  ┌────────────────────────────────────┐  │  card #FFFFFF、角丸 18、内側 28×24
│  │ 予約が完了しました        ← title   │  │  22/800 text、行間 1.4、下余白 12
│  │ ┌──────────────────────────────┐   │  │  番号の箱（確定・リマインドだけ）
│  │ │          予約番号            │   │  │  fill #EFE9DF、角丸 12、内側 16
```

### 3.2 種類ごとの部品

| kind                 | 見出し（`title` の例）          | 番号の箱 | ボタン | 備考                                         |
| -------------------- | ------------------------------- | -------- | ------ | -------------------------------------------- |
| `booking_confirmed`  | 予約が完了しました              | ○        | ○      | 箱のラベルは `bookings.kind` で変える        |
| `reminder`           | 明日の受け取りのお知らせ        | ○        | ○      | 同上                                         |
| `cancelled_by_staff` | 店舗によりキャンセルされました  | —        | ○      | 番号は `body` の文中にある                   |
| `listing_changed`    | 受け取り期間が変わりました      | —        | ○      | 新しい日時は `body` の文中にある             |
| `cancelled_by_user`  | （設計_利用者キャンセルの通知） | —        | ○      | 追加されたら `cancelled_by_staff` と同じ扱い |

ボタンは `APP_WEB_URL` が設定されているときだけ出す。先は `APP_WEB_URL` ＋ `deepLink(n)`（上の 5 種はすべて `/bookings/<booking_id>`）。

### 3.3 番号の箱

`NumberCard.tsx`（白地・60/900・字間 8.4）をメール向けに縮めたもの。カードが白なので箱は `fill` の塗りにし、`email_change` のアドレス表示と同じ作り（塗り・角丸 12）にする。

| 部位   | 指定                                                                                                                                                                                                                            |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 箱     | `bgcolor="#EFE9DF"`、`background:#EFE9DF; border-radius:12px; padding:16px`、幅 100%、中央寄せ                                                                                                                                  |
| ラベル | 13/700 `textWeak`。`bookings.kind` が `product` → 予約番号、`event` → 申し込み番号、`job` → 受付番号（`src/features/bookings/derive.ts` の `numberLabel` と同じ 3 語。helpers.ts に同じ対応表を書き、コメントで出どころを示す） |
| 番号   | 32/900 `text`、`letter-spacing:.12em`、`line-height:1.2`、`font-variant-numeric:tabular-nums`。`bookings.number` の文字列をそのまま（アプリも桁埋めや区切りはしていない）                                                       |

### 3.4 配色・文字

認証メールの 3.2〜3.4 と同じ値を使う（`bg`・`card`・`text`・`textSub`・`textWeak`・`divider`・`accent`・`fill`、フォントスタック、サイズと行間）。新しい色は足さない。

### 3.5 文面（HTML が足す部分）

`title`・`body` は DB の値をそのまま。HTML 側で足す文言は次の 4 つだけ。

| 部位         | 文言                                                                                                                                                                                                                              |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| プリヘッダー | `body` と同じ文（受信箱の一覧に出る。本文では非表示）                                                                                                                                                                             |
| ボタン       | `予約・申込を見る`（アプリの下タブ名と同じ）                                                                                                                                                                                      |
| 補足         | `アプリの「予約・申込」からも確認できます。`（ボタンの有無にかかわらず出す。現状の `text` にある文と同じ）                                                                                                                        |
| フッター     | `このメールは LocalEC に登録されたメールアドレス（<宛先>）宛てに、予約・申込の状況をお知らせするために送信しました。送信専用のため、返信には対応できません。予約・申込に関するメールは、アプリの通知設定に関わらずお送りします。` |

フッターの最後の一文は、マイページの「お知らせ通知」スイッチがプッシュだけを止めるものであることを先に伝えるため（取引メールは `notifications_enabled` を見ずに送る。設計_通知の配信 3 章）。

`text`（テキスト版）は現状の形を保ち、ボタンがあるときだけ URL の行を足す。

```
<body>

詳細：<APP_WEB_URL>/bookings/<id>      ← APP_WEB_URL があるときだけ

アプリの「予約・申込」からも確認できます。

※このメールは送信専用です。
```

## 4. 実装

### 4.1 `helpers.ts`（純粋関数。Deno の API を使わない）

```ts
export type EmailInput = {
  kind: string;
  title: string;
  body: string;
  /** 送り先（フッターに出す） */
  to: string;
  /** 番号の箱。booking_confirmed と reminder で、予約が引けたときだけ渡す */
  booking?: { number: string; kind: "product" | "event" | "job" } | null;
  /** ボタンの先。APP_WEB_URL が未設定なら null（ボタンなし） */
  url?: string | null;
};

/** 件名・テキスト・HTML。件名とテキストの形は現状のまま */
export function emailContent(n: EmailInput): {
  subject: string;
  text: string;
  html: string;
};

/** 番号の箱を出す種類 */
export const NUMBER_BOX_KINDS: ReadonlySet<string> = new Set([
  "booking_confirmed",
  "reminder",
]);

/** &, <, >, ", ' をエスケープする。title・body・number・to のすべてに通す */
export function escapeHtml(s: string): string;

/** APP_WEB_URL（末尾の / は落とす）＋ deepLink(n)。APP_WEB_URL が空なら null */
export function emailLink(
  base: string | undefined,
  n: NotificationLike,
): string | null;
```

- HTML はテンプレート文字列で組む。構造と style は `magic_link.html` を正とし、カードの中身だけ 3.1 の順に差し替える。フォントスタックは定数 `FONT` にまとめて毎回インラインで書く
- `body` の改行（`\n`）は `<br />` にする（今の SQL は改行を入れていないが、将来入っても崩れないように）
- `<style>`・外部画像・Web フォントは使わない。`<meta name="color-scheme" content="light">` など head のメタは認証メールと同じ
- 番号の箱の有無は `NUMBER_BOX_KINDS.has(kind) && booking` で決める。種類が該当しても予約が引けなければ出さない（落とさない）

### 4.2 `index.ts` の `sendEmails`

- 送る前に、`booking_id` のある通知の分だけ `bookings` から `id, number, kind` をまとめて 1 回で引く（`.in('id', ids)`）。`profiles` の取得と同じ場所でよい
- `emailContent` に `to`（`profiles.email`）、`booking`、`url`（`emailLink(Deno.env.get('APP_WEB_URL'), n)`）を渡し、戻り値をそのまま `sendMail` に展開する（`subject`・`text`・`html`）
- エラー処理・`email_sent_at` の更新は現状のまま

### 4.3 環境変数 `APP_WEB_URL`

| 場所                               | 値                                                                                                                |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `app/supabase/.env.example`        | `APP_WEB_URL=http://localhost:8081`（コメント：Web 版の公開 URL。通知メールのボタンの先。空ならボタンを出さない） |
| ホスト版（`supabase secrets set`） | `https://<slug>.expo.app`（設計_デプロイ 4 章 C で Web を出したあとに設定。`site_url` と同じ値）                  |

`SUPABASE_URL` や `site_url` から導けないので別に持つ（`site_url` は Auth の設定で Edge Function からは読めない）。

## 5. テスト（`sendHelpers.test.ts`）

- `escapeHtml`：`<b>&"'` が実体参照になる
- `emailLink`：`APP_WEB_URL` が空・未定義なら `null`。末尾 `/` ありなしのどちらでも `https://x.expo.app/bookings/<id>` になる
- `emailContent`：
  - 件名が `【LocalEC】<title>`、`text` に `body` と「アプリの「予約・申込」からも確認できます。」が入る（現状と同じ）
  - `booking_confirmed` ＋ `booking` → HTML に番号とラベル「予約番号」が入る。`event` なら「申し込み番号」、`job` なら「受付番号」
  - `cancelled_by_staff` ＋ `booking` → 番号の箱が出ない
  - `url` なし → `<a href` が無い。あり → `href="<url>"` が 1 つ、ボタン文言「予約・申込を見る」
  - `title` に `<script>` を入れても HTML にそのまま現れない

## 6. 確認手順

ローカルでも Resend で本物の受信箱に送る（README「メール（Resend）」。`t-hasebe@meincoltd.com` にしか届かない）。手順は [動作確認手順_フェーズ1.md](動作確認手順_フェーズ1.md) と README「動作確認」に沿う。

1. 見た目の素早い確認：Jest かスクラッチのスクリプトで `emailContent` の `html` をファイルに書き出し、ブラウザで開く。幅 390px と 1280px で崩れないことを見る。番号の箱あり・なし、ボタンあり・なしの 4 通りを見る
2. `supabase/.env` に `APP_WEB_URL=http://localhost:8081` を入れ、`npm run functions` を再起動する
3. 利用者として商品を予約する → 確定メール：番号の箱・本文・ボタンが出る。ボタンで Web 版の予約詳細が開く（未ログインならログイン後にその画面へ戻る）
4. Studio で `select public.emit_reminders('same_day');` → リマインドのメールに番号の箱が出る
5. 運営としてキャンセル → キャンセルのメールに番号の箱が無く、本文中の番号は読める
6. 運営で受け取り期間を変える → 変更のメール
7. 受信箱で次を確認する
   - Gmail（Web）：カードの角丸・ボタン・番号の箱の塗りが出る。プリヘッダーが一覧に出て本文には出ない
   - Gmail（iOS または Android アプリ）：ダークモードで番号・本文・ボタンが読める
   - iOS メール：ライト表示が保たれる
8. `APP_WEB_URL` を空にして 3 をもう一度 → ボタンが無く、補足の文だけが出る

## 8. 後続・未決

- **アプリを直接開くリンク**：開発ビルドで Universal Links／App Links を入れたら、同じ https の URL が OS 経由でアプリを開く（設計_デプロイ 8 章）。メール側は変更不要
- **サービス名・ロゴ画像**：認証メールの 7 章と同時に変える
- **問い合わせ先**：店舗の電話番号をメールに入れるかは未決。入れるなら `stores.phone` を `bookings` と一緒に引いて、本文の下に「お問い合わせ：<店舗名> <電話>」を足す（文面は SQL ではなく HTML 側。番号の箱と同じ「1 つの値を見せる」扱い）
- **新着通知のメール化**：要件上はプッシュだけ。メールにするなら `notification_wants_email` と `EMAIL_KINDS` を変え、ボタンの先は `/listings/<id>` になる（`deepLink` が既に対応）
