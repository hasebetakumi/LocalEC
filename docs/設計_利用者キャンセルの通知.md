# 設計：利用者が自分でキャンセルしたときの通知

利用者が U-21 で予約・申し込み・応募をキャンセルしたとき、本人にキャンセル完了のメールを送る。2026-10-14 に決定。

## 1. 背景と判断

- 現状、通知の契機は「予約確定・リマインド・店舗キャンセル・期間変更・新着」の 5 つで、利用者自身のキャンセル（`cancel_booking`）は何も送っていない（要件 U-30 にも含まれていなかった）
- しかし利用者にとっては「本当にキャンセルできたか」の証跡が残らない。店舗キャンセルと同様にメールで残す
- **プッシュは送らない**。自分で押した直後にバナーが出ても意味がないため。メールだけ（判断：取引通知は「プッシュ＋メール」が原則だが、本人操作の確認は例外とする）

## 3. 文言

店舗キャンセル（`staff_cancel_booking`）と同じ形。種類（`bookings.kind`）で名詞を変える。

| kind | title | body |
| --- | --- | --- |
| product | 予約をキャンセルしました | 「{掲載タイトル}」の予約（番号 {number}）をキャンセルしました。 |
| event | 申し込みをキャンセルしました | 「{掲載タイトル}」の申し込み（番号 {number}）をキャンセルしました。 |
| job | 応募を取り消しました | 「{掲載タイトル}」の応募（番号 {number}）を取り消しました。 |

- 件名は既存どおり `【LocalEC】{title}`、末尾の定型文（「アプリの『予約・申込』からも確認できます」）も既存どおり
- `booking_id`・`listing_id` を入れる（タップ先は `/bookings/{id}`。メールだけなので実際には使わないが、他と同じ形で残す）
- `dedupe_key` は不要（`status <> 'reserved'` のチェックで二重キャンセルは起きない）
