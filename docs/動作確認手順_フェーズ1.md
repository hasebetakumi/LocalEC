# 動作確認手順（フェーズ1・30 分版）

ローカルで主要な機能を一通り確かめる手順。上から順に実行する。各項目は「やること」と「→ こうなれば OK」の組。

## 0. はじめに

- 使うアカウントは `t-hasebe@meincoltd.com` の 1 つだけ。利用者としても運営としても使う（Resend がこのアドレスにしか送れないため）
- 受信箱をブラウザで開いておく。ログインのリンクも通知もここに届く
- 届くメールは 7 通前後
- Docker を起動しておく。`supabase/.env` の `SMTP_PASS` に Resend の API キーが入っていること（初回の設定は README「初回だけ」）
- 利用者画面は http://localhost:8081 、運営画面はマイページの「スタッフメニュー」から

## 1. 準備（5 分）

コマンドは `app/` の中で実行する。

- [ ] **1-1** データを初期状態にする

  ```bash
  npm run db:reset
  ```
- [ ] **1-2** 端末 A で通知を送る関数を起動する（開いたままにする）

  ```bash
  npm run functions
  ```
- [ ] **1-3** 端末 B でアプリを起動する（開いたままにする）

  ```bash
  npm run web
  ```

  → ブラウザで http://localhost:8081 が開き、ホームに商品のカードが写真付きで並ぶ
- [ ] **1-4** Chrome の開発者ツール（F12）で端末エミュレーションをオンにし、幅を 390 にする
- [ ] **1-5** お知らせの既読を消す。開発者ツールの「Console」で次を実行し、ページを再読み込みする

  ```js
  localStorage.removeItem('notices.read');
  ```

  → お知らせの既読は DB ではなくブラウザに保存している（未ログインでもベルに未読数を出すため）。シードのお知らせは ID が固定なので、`db:reset` しても一度開いたものは既読のまま。これを消さないと 2-2 のバッジと「NEW」が出ない

## 6. 通知の配信を SQL で確かめる（3 分）

Studio（http://localhost:58323 ）の「SQL Editor」で実行する。

- [ ] **6-1** 本日のリマインドを作って送る

  ```sql
  select public.emit_reminders('same_day');
  select public.invoke_send_notifications();
  ```

  → 1 つ目は `0`（新米は受け取り済みなので対象なし）。エラーが出なければ OK
- [ ] **6-2** 送った結果を見る

  ```sql
  select kind, title, email_sent_at, email_error, push_error
    from public.notifications order by created_at desc limit 10;
  ```

  → `booking_confirmed` 3 行と `cancelled_by_user` 1 行（3-6）と `cancelled_by_staff` 1 行。`email_sent_at` に時刻が入り `email_error` は空。`push_error` は `done`（端末がないので「プッシュは送らない」で確定した印。`cancelled_by_user` は端末があっても最初から `done`）

## 8. スマホ（iOS / Android の Expo Go）で確かめるとき

確認する項目（2〜7 章）は Web と同じ。違うのは準備と、タブに頼っている操作だけ。iOS と Android の差はプッシュ通知の有無のみ（2-4・3-2・3-4・3-6・5-5 の **iPhone** の行）。`npm run ios` / `npm run android` はシミュレータ・エミュレータ用で、この環境には入っていないので使わない。

- [ ] **8-1** 準備（1 章の置き換え）
  - `app/.env` の `EXPO_PUBLIC_SUPABASE_URL` を `localhost` ではなく PC の IP アドレス（`http://192.168.x.x:58321`）にする
  - ログインを試すなら `supabase/.env` に `SUPABASE_AUTH_EXTERNAL_URL=http://<PC の IP>:58321/auth/v1` を書き、`npx supabase stop && npx supabase start`
  - Windows（WSL2）はファイアウォールで 8081 と 58321 を許可しておく（Windows と Hyper-V の両方。Wi-Fi が「パブリック」扱いだと効かない）
  - 1-3 は `npm run web` の代わりに次を実行し、Expo Go（CLI と同じアカウントでログイン済み）で QR コードを読む。LAN 接続（`npm run start:app`）だとログインのリンクから戻れない

    ```bash
    npm run start:tunnel
    ```

  - 1-4（Chrome の端末エミュレーション）は不要
  - 1-5（既読を消す）はスマホでは Expo Go のアプリデータを消すしかない（iOS は Expo Go を入れ直す、Android は設定の「ストレージを消去」）。消さない場合、一度開いたお知らせは「NEW」に戻らないので 2-2 は件数が合わなくてもよい
- [ ] **8-2** ログイン（2-4）
  → 2-4 の「スマホ」の行のとおり。「Expo Go で開きますか」が出たら許可。PC で送ったメールをスマホで開く、はできない
- [ ] **8-3** 「ブラウザの別タブ」（4-6、5-3〜5-6）
  → スマホにはタブがないので、運営画面から戻って利用者側の画面を開く。PC の Web を「利用者のタブ」として併用してもよいが、PC 側は別にログインが要り、メールを 1 通余計に使う。「再読み込み」は引っ張って更新するか、画面を開き直す
- [ ] **8-4** SQL（6 章）
  → PC の Studio で同じ SQL を実行する
- [ ] **8-5** プッシュ通知（6-2 の見え方）
  - iPhone：2-4 で許可していれば 3-2・3-4・5-5 でプッシュが届いている。6-2 では `push_error` が空で `push_sent_at` に時刻が入る（`cancelled_by_user` だけはプッシュを送らないので `done`）
  - Android の Expo Go：プッシュが使えない（SDK 53 以降）。6-2 は Web と同じ `done`。実際の受信は開発ビルドで確かめる
- [ ] **8-6** 片付け（7 章のあと）
  → `app/.env` の URL と `supabase/.env` の `SUPABASE_AUTH_EXTERNAL_URL` を戻す（Web だけで確認する日は `localhost` に戻し、Supabase を再起動する）

## つまずいたとき

| 症状                               | 見るところ                                                                                                                        |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| ログインのメールが届かない         | `supabase/.env` の `SMTP_PASS`。変えたら `npx supabase stop && npx supabase start`                                          |
| 確定メールが来ない                 | 端末 A の `npm run functions` が動いているか。`select email_error from public.notifications order by created_at desc limit 5;` |
| 「予約へ進む」で `Database error` | `npm run db:reset` をやり直す                                                                                                   |
| 数や表示が手順と合わない           | 時刻でシードの商品が期限切れになることがある。`db:reset` で今日基準に作り直される                                               |
| 2-2 のバッジ・「NEW」が出ない | 既読がブラウザに残っている。1-5 の `localStorage.removeItem('notices.read')` を実行して再読み込み |
| Expo Go でアプリが開かない・商品が出ない | Metro（端末 B）が動いているか → `app/.env` の IP が今の PC の IP か（変えたら `npx expo start --tunnel -c`）→ 両ファイアウォール、の順に見る |
| スマホでログインのリンクを押しても戻らない | `supabase/.env` の `SUPABASE_AUTH_EXTERNAL_URL`（書いたら Supabase 再起動）と、端末 B がトンネル起動か |
| `start:tunnel` が「failed to start tunnel」で落ちる | Expo 共有の ngrok の上限のことが多い。時間をおいて再試行。ログイン済みなら `npm run start:app`（LAN）でログイン以外は確認できる |
