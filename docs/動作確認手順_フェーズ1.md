# 動作確認手順（フェーズ1・30 分版）

ローカルで主要な機能を一通り確かめる手順。上から順に実行する。各項目は「やること」と「→ こうなれば OK」の組。

## 0. はじめに

- 使うアカウントは `t-hasebe@meincoltd.com` の 1 つだけ。利用者としても運営としても使う（Resend がこのアドレスにしか送れないため）
- 受信箱をブラウザで開いておく。ログインのリンクも通知もここに届く
- 届くメールは 6 通前後
- Docker を起動しておく。`supabase/.env` の `SMTP_PASS` に Resend の API キーが入っていること（初回の設定は README「初回だけ」）
- 利用者画面は http://localhost:8081 、運営画面はマイページの「スタッフメニュー」から

## 1. 準備（5 分）

コマンドは `app/` の中で実行する。

- [ ] **1-1** データを初期状態にする

  ```bash
  npm run db:reset
  ```

- [ ] **1-2** 端末 A で通知を送る関数を起動する（開いたままにする）

  ```bash
  npm run functions
  ```

- [ ] **1-3** 端末 B でアプリを起動する（開いたままにする）

  ```bash
  npm run web
  ```

  → ブラウザで http://localhost:8081 が開き、ホームに商品のカードが写真付きで並ぶ

- [ ] **1-4** Chrome の開発者ツール（F12）で端末エミュレーションをオンにし、幅を 390 にする

## 2. 利用者：見る・ログインする（5 分）

- [ ] **2-1** ホームで「朝採れ野菜セット」を開く
  → 写真が灰色で「売り切れ」、赤い帯「売り切れのため、予約できません。」、ボタンが押せない

- [ ] **2-2** 戻って、ベル（見出しの右）を押す
  → バッジ「3」が付いていて、お知らせが 3 件出る。1 件開いて戻ると「NEW」が消える

- [ ] **2-3** 下タブ「商品」→ カテゴリ「お米」→「新米コシヒカリ 5kg」→「予約へ進む」
  → ログイン画面になる

- [ ] **2-4** メールアドレスに `t-hasebe@meincoltd.com` を入れ「ログイン用リンクを送る」→ 届いたメールのリンクを押す
  → アプリに戻り、そのまま「予約内容の確認」（新米の数量選択）が開く

## 3. 利用者：予約・申し込み・キャンセル（7 分）

- [ ] **3-1** 「＋」を 1 回押して数量 2 にし、「予約を確定する」
  → テラコッタ色の「予約が完了しました」。4 桁の予約番号が出る。番号を書いておく：`____`

- [ ] **3-2** 受信箱
  → 数秒で「【LocalEC】予約が完了しました」が届く

- [ ] **3-3** 下タブ「予約・申込」→ 新米の行を押す
  → 「予約の詳細」。番号、状態「予約中」、お支払い 5,600円、下に「… 18:00 までキャンセルできます」

- [ ] **3-4** 下タブ「イベント・求人」→「親子でさつまいも掘り体験」→「参加を申し込む」→ 人数 2 →「申し込みを確定する」
  → **緑色** の「申し込みが完了しました」。「【LocalEC】申し込みが完了しました」のメールも届く

- [ ] **3-5** 下タブ「予約・申込」
  → 「今日」の下に新米、別の日付の下にイベント（緑の点）が並ぶ

- [ ] **3-6** イベントの行 →「申し込みをキャンセルする」→ 赤い「キャンセルする」
  → 状態が「キャンセル」になる。「履歴」に移ると灰色の「キャンセル」で出る

- [ ] **3-7** 下タブ「マイページ」
  → 名前「山田 太郎」とメール、黒い「スタッフメニュー」のカードがある

## 4. 運営：予約の処理（7 分）

- [ ] **4-1** 「スタッフメニュー」を押す
  → 「店舗を選ぶ」。店舗カード 3 枚。「あけぼの農園 直売所」に「本日の予定 1件」

- [ ] **4-2** 「番号で探す」に 3-1 の番号を入れる
  → 新米の予約が 1 件出る。押すと受け取り処理の画面（番号・氏名・「受け取り済みにする」）。押さずに左上「‹ 店舗を選ぶ」で戻る

- [ ] **4-3** 「あけぼの農園 直売所」のカードを押し、「予約」タブ
  → 「本日」「未完了」に新米の行が 1 つ。件数行に「受け取り 1件（合計 5,600円）」

- [ ] **4-4** 新米の行 →「受け取り済みにする」
  → 一覧に戻り「本日の予定はありません」。「未完了 ▾」を「すべて」にすると緑の「受け取り済み」ピルで出る

- [ ] **4-5** 「掲載」タブ →「新米コシヒカリ 5kg」→ 右上「⋯」→「編集」
  → 黄色の注意「予約が2件入っています」。数量と受け取り期間だけ変更できる。「×」で閉じる

- [ ] **4-6** 利用者側の確認：ブラウザの別タブで http://localhost:8081 →「予約・申込」→「履歴」
  → 新米が「受け取り済み」で出る。このタブは残す（以後「利用者のタブ」）

## 5. 運営：掲載を公開する・店舗からキャンセルする（6 分）

- [ ] **5-1** 運営のタブで右上「＋ 掲載」→「商品」→ 何も入れずに「公開する」
  → 必須の欄が赤枠になり「◯◯を入力してください」

- [ ] **5-2** タイトル `動作確認のお弁当`、カテゴリ「お弁当」、価格 `500`、数量 `10`、受け取り開始に明日 11:00、終了に明日 13:00 を入れて「公開する」
  → 一覧に「動作確認のお弁当」が「公開」で出る（締切と公開終了は受け取り終了に自動で揃う）

- [ ] **5-3** 利用者のタブでホームを再読み込み
  → 「新着」の先頭に「動作確認のお弁当」が出る。開くと「残り10食」500円

- [ ] **5-4** 利用者のタブで「動作確認のお弁当」→「予約へ進む」→「予約を確定する」
  → 完了画面。確定メールも届く

- [ ] **5-5** 運営のタブで「予約」タブ →「本日 ▾」→「今後」→「動作確認のお弁当」の行 → 赤い「キャンセルにする」→ シートの「キャンセルにする」
  → 一覧に戻る。受信箱に「【LocalEC】店舗によりキャンセルされました」が届く

- [ ] **5-6** 利用者のタブで「予約・申込」→「履歴」を再読み込み
  → 「動作確認のお弁当」が「キャンセル」で出る

## 6. 通知の配信を SQL で確かめる（3 分）

Studio（http://localhost:58323 ）の「SQL Editor」で実行する。

- [ ] **6-1** 本日のリマインドを作って送る

  ```sql
  select public.emit_reminders('same_day');
  select public.invoke_send_notifications();
  ```

  → 1 つ目は `0`（新米は受け取り済みなので対象なし）。エラーが出なければ OK

- [ ] **6-2** 送った結果を見る

  ```sql
  select kind, title, email_sent_at, email_error, push_error
    from public.notifications order by created_at desc limit 10;
  ```

  → `booking_confirmed` 3 行と `cancelled_by_staff` 1 行。`email_sent_at` に時刻が入り `email_error` は空。`push_error` は `done`（端末がないので「プッシュは送らない」で確定した印）

## 7. 片付け（1 分）

- [ ] **7-1** 「マイページ」→「ログアウト」
  → 未ログインの表示（「ログイン・新規登録」）になる

- [ ] **7-2** データを戻し、端末 A・B を Ctrl+C で止める

  ```bash

  ```

## つまずいたとき

| 症状 | 見るところ |
| --- | --- |
| ログインのメールが届かない | `supabase/.env` の `SMTP_PASS`。変えたら `npx supabase stop && npx supabase start` |
| 確定メールが来ない | 端末 A の `npm run functions` が動いているか。`select email_error from public.notifications order by created_at desc limit 5;` |
| 「予約へ進む」で `Database error` | `npm run db:reset` をやり直す |
| 数や表示が手順と合わない | 時刻でシードの商品が期限切れになることがある。`db:reset` で今日基準に作り直される |
